# Development log — 2026-09-06

## Product direction agreed today

MabarQueue is a creator engagement platform for livestream gaming, not only a queue tool. The product should support multiple games while keeping two shared features across every game:

- **Mabar Queue** — viewers purchase game sessions and enter the creator's queue.
- **Donate** — viewers can send support and trigger an overlay popup without entering the queue.

Game-specific modules depend on the creator's selected game. The first supported game is **Mobile Legends**. Its dashboard can include Comment Album alongside Mabar Queue and donations. **PUBG Mobile** and **Valorant** are represented as coming soon. Their dashboards should only expose capabilities that make sense for those games.

The creator's active game must be stored as workspace data. This becomes the source for dashboard labels, queue capacity, player ID terminology, onboarding options, and game-specific modules.

### Migration from Stripe to CHIP Collect

Commit `1bb7fe5` replaced Stripe with **CHIP Collect** as the active payment provider.

- Removed the Stripe SDK, Connect onboarding routes, Stripe webhook, account-status module, and payment return/refresh pages.
- Added a server-only CHIP client using the CHIP purchase API, bearer authentication, brand ID, and integer-sen amounts.
- Added raw-body CHIP callback signature verification using CHIP's public key.
- Re-fetches each purchase from CHIP before fulfilment instead of trusting callback data alone.
- Keeps payment fulfilment idempotent so callback retries cannot credit a viewer twice.
- Added an append-only creator ledger for earnings, reversals, and future payouts.
- Retained `stripe` only as a legacy provider value so old records remain readable.
- Changed the fee model: creators keep the full listed price and the service fee is added to the viewer's checkout total.
- Stores base amount, platform fee, processing fee, total charged, creator entitlement, and platform net as separate integer-sen values.
- Leaves the CHIP processing fee at zero until the real fee schedule is confirmed instead of inventing a rate.
- Updated the creator Payments page to show accrued balances and explain that withdrawals are not open yet.
- CHIP Send or another verified creator payout mechanism is still pending. CHIP Collect currently settles into the MabarQueue merchant account, while the internal ledger records the amount owed to each creator.

### Local CHIP callback fix

Commit `fe3cb8f` fixed checkout creation failing because CHIP rejects callback URLs with custom ports such as `localhost:3000`.

- Added `CHIP_CALLBACK_ORIGIN` for a public HTTPS callback origin such as an ngrok tunnel.
- Applies the override only to the server-to-server success callback; browser success and failure redirects continue using the request origin.
- Fails early with an actionable configuration message when a local callback origin is invalid.
- Added callback-origin resolution tests.

## Current payment model

- Active provider: **CHIP Collect**.
- Money unit: integer sen.
- Viewer charge: creator's listed price plus the configured MabarQueue service fee.
- Creator entitlement: full listed price.
- Payment confirmation: verified CHIP callback followed by a server-side purchase fetch.
- Creator balance: derived from append-only ledger entries.
- Withdrawals: unavailable until the payout/marketplace flow is confirmed and implemented.
- Legacy Stripe records remain readable, but new checkout and callback flows use CHIP.
